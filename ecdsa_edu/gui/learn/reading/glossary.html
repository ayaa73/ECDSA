TermMeaning
Elliptic curveThe set of points (x, y) with y² = x³ + a·x + b (mod p), plus the point at infinity O. The points form a group under "point addition".
pThe prime that defines the field: all coordinates are numbers mod p.
a, bThe curve coefficients. secp256k1 uses a = 0, b = 7.
O (point at infinity)The identity of the group: P + O = P. It has no coordinates.
Generator GA fixed public point that everyone uses. Every key is a multiple of G.
Order nThe smallest positive n with n·G = O. All scalars (d, k, r, s) live mod n. On toy-17, n = 19.
Cofactor h(number of points on the curve) / n. It is 1 for secp256k1, P-256 and toy-17.
Scalar multiplicationk·P = P + P + … + P (k times), computed quickly with double-and-add.
ECDLPElliptic-curve discrete logarithm problem: given P and Q = d·P, find d. Infeasible for 256-bit curves; this is what keeps d secret.
Private key dA secret random number with 1 ≤ d ≤ n−1.
Public key QQ = d·G. Safe to publish because of the ECDLP.
Hash eThe message hash (e.g. SHA-256) as an integer, truncated to the bit length of n.
Nonce kA per-signature secret number. Must never repeat and never be predictable or biased.
RThe point k·G computed while signing.
rFirst half of the signature: the x-coordinate of R, mod n.
sSecond half of the signature: s = k−1(e + r·d) mod n. Binds the message, the key and the nonce together.
ws−1 mod n, computed by the verifier.
u1, u2The verifier's scalars: u1 = e·w, u2 = r·w (mod n).
Modular inversex−1 mod n is the number y with x·y = 1 mod n. It exists when gcd(x, n) = 1, which is always true for 1 ≤ x ≤ n−1 when n is prime.
RFC 6979A standard for deriving k deterministically from d and the message hash using HMAC, so no random number generator is needed when signing.
Nonce reuseSigning two messages with the same k. Leaks the private key from just two signatures.
Low-sThe convention of using s ≤ n/2. Since (r, n−s) is also valid, requiring low-s gives each message one signature.
MalleabilityBeing able to change a valid signature into a different valid signature without the key, e.g. (r, s) → (r, n−s).
DERA standard binary encoding of (r, s), used by most crypto libraries and certificates.
Constant-time codeCode whose running time doesn't depend on secret values, so timing measurements reveal nothing.
secp256k1A 256-bit curve from SEC 2 with a = 0, b = 7. Used by Bitcoin and Ethereum.
P-256A 256-bit NIST curve (also called secp256r1), used in TLS and many other protocols.
SEC 1, FIPS 186-5The standards that define ECDSA signing and verification.
