4 · Key pairs: private key d and public key Q

Before anyone can sign, they need a key pair. It has two halves that belong together:

NameWhat it isWho knows itUsed for
Private key da whole number, 1 ≤ d ≤ n − 1only the ownercreating signatures
Public key Qa point on the curve, Q = d · Geverybodychecking signatures

Here G is the curve's base point and n is its order (the smallest positive number with n · G = O, the point at infinity). Both are fixed, public parts of the curve.

How a key pair is generated

  1. Pick d at random from 1, 2, …, n − 1. Every value must be equally likely.
  2. Compute Q = d · G with scalar multiplication (double-and-add, see page 3).
  3. Keep d secret. Publish Q.

That is all. There is no "encryption" step: the public key is just the result of a multiplication on the curve.

Worked example on the toy curve

Curve toy-17: y² = x³ + 2x + 2 (mod 17), base point G = (5, 1), order n = 19.
Suppose we pick the private key d = 7. In binary, 7 = 111.

Double-and-add reads the bits from left to right. For every bit: double; if the bit is 1: add G.

BitOperationRunning point
1start with G1·G = (5, 1)
1double, then add G2·G = (6, 3)  →  3·G = (10, 6)
1double, then add G6·G = (16, 13)  →  7·G = (0, 6)

So the key pair is: private key d = 7, public key Q = (0, 6).

Try it: open the Keys tab, choose curve toy-17, type 7 and press "Compute Q from this d". The panel on the right shows exactly these steps.

Why d must be truly random

  • If an attacker can guess d, they own the key. A d taken from a weak generator (a timestamp, random.random(), a small number) can be guessed quickly.
  • If d is biased (some values more likely than others), the search becomes easier.

ECDSA Lab therefore takes d from the operating system's cryptographic random generator (Python's secrets module): d = secrets.randbelow(n − 1) + 1. randbelow gives a uniform number in 0 … n − 2, and adding 1 moves it to 1 … n − 1.

Why 0 and n are not allowed

  • d = 0 would give Q = O (the point at infinity), which is not a usable public key.
  • d = n gives the same result, because n · G = O. In general d and d + n produce the same Q, so only 1 … n − 1 are different keys.

Checking a public key you receive

A public key from somebody else is untrusted input. Before using it, check that:

  1. Q is not the point at infinity;
  2. both coordinates are in the range 0 … p − 1;
  3. Q satisfies the curve equation y² = x³ + ax + b (mod p);
  4. n · Q = O, i.e. Q is one of the multiples of G.

Skipping these checks allows "invalid-curve" tricks, where an attacker sends a point from a different, weaker curve. ECDSA Lab runs all four checks whenever a public key is imported or loaded.

Summary

  • Private key: a random number d with 1 ≤ d ≤ n − 1.
  • Public key: the point Q = d · G.
  • d → Q is fast. Q → d is the hard problem explained on the next page.
